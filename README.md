# 职业培训报名转化公开表

按招生渠道和培训项目核算月度报名转化，复核后交付公开汇总。

榆桥职业培训中心招生组，合作服务三个招生渠道，开设三类就业技能培训项目。 招生员合并社区、公众号和就业服务站的月度受理记录，分析员按学员和月份核对重复登记。管理员和分析员核对源明细，查看者使用管理员复核通过的公开汇总。中心将通过复核的结果 CSV 交付合作单位。

- 登记和确认回执各有一行，同一学员在一个月内可能被重复计数或同时分到多个渠道。
- 直接平均各项目转化率，容易让小班和大班对总体结果产生相同影响。
- 空出小样本单元格后，如果保留合计，读者仍能通过减法算出被遮住的数。

## 业务模块

| 模块 | 用途 |
|---|---|
| 招生月报总览 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 受理明细 | 下载「榆桥职训受理_202610-11.csv」并核对字段。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。 |
| 公开口径 | 选择批次和参数并提交后台计算，可从运行列表追踪状态。 |
| 报名转化交叉表 | 查看业务指标、证据表和解释，通过来源链接回查数据。 |
| 公开披露复核 | 查看待处理或已完成记录。复核主管可提交公开披露复核及依据。 |
| 公开表交付 | 按批查找结果，核对复核状态并下载相应的 CSV。 |

## 启动

```bash
cp -n .env.example .env
docker compose config --quiet
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

浏览器访问 `http://127.0.0.1:18281`。FastAPI 文档位于 `http://127.0.0.1:19281/docs`，MySQL 8 的本地端口为 `17781`。本批在带空格和中文的工作区验证启动。

## 演示流程

1. 11 月 21 日 09:00，招生员汇总 10 月归档和 11 月截至 20 日的受理记录，生成「榆桥职训受理_202610-11.csv」。
2. 09:20 在受理明细导入 CSV，检查受理日期、学员编号和报名确认值。
3. 09:30 在公开口径选择 2026-11，沿用两类人数均至少 5 人的门槛，生成渠道 × 项目交叉表。
4. 09:40 核对社区转介 × 养老照护为 12 / 20，社区转介 × 烘焙实训被抑制，整张表省略边际合计。
5. 10:00 切换至 2026-10 核对 62 / 125 的总体转化，检查原始人数加权口径。
6. 10:30 复核员检查历史版本与当前结果可否联立推算，记录发布决定。
7. 11:00 在公开表交付下载复核通过的结果 CSV，供合作单位使用。

## 计算口径

- 受理日期所在自然月为统计月份。每名学员每月只计一次，以最早受理日的渠道和项目归属；最早同日有不同归属时须修正源记录。
- 同月只要有归属项目的确认报名，即记为一次转化，确认记录可以来自其他渠道。各格转化率等于确认人数 ÷ 去重受理人数。
- 合计转化率以分子之和除以分母之和。行列使用预先公布的渠道和项目名册，空组合照常占位。
- 确认与未确认人数各自都须达到门槛，否则整格隐藏人数和比率，图表跳过该格，并省略所有行、列及总体合计。零受理组合使用同一抑制标记。
- 小单元格抑制用于控制单张交叉表的披露。它不提供差分隐私保证，修订版、不同门槛和外部数据仍可能被联立推算。发布前应对照已有版本复核。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | MySQL 8 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
